## Platform

macos

Native macOS app (SwiftUI + AppKit), macOS 15+, menu bar agent (`LSUIElement`). Not one of impeccable's first-class platform values (web/ios/android/adaptive); recorded as `macos` and designed to Apple HIG for menu bar utilities. Confirmed with the user 2026-09-13.

## Stack

Existing codebase: SwiftUI + AppKit, `MenuBarExtra` for the menu, `Settings {}` scene for preferences, `NSPanel`-style floating panel for the meeting prompt. Project generated via XcodeGen (`project.yml` is source of truth). Shells out to `ffmpeg`, `whisper.cpp`, Groq/Gemini for the pipeline.

## Users

Junior (Sparrow, IT consultancy) and solo/small-team professionals who take meeting notes. Single-user, local-first: no accounts, no cloud storage, no telemetry. The user runs the app on their own Mac during meetings (Zoom/Meet/Comet/etc.) and reads the generated notes afterward in `~/MeetingNotes`.

## Product Purpose

Capture meeting audio (system + microphone), transcribe locally, and generate structured notes with AI, in the style of Granola. Success is: no meeting is ever lost, the transcript is complete and faithful, and the notes are usable without the user babysitting the app. The app should be nearly invisible while working and only speak up when it needs a decision.

## Positioning

Local-first meeting notes on macOS: audio-triggered auto-start (reads which processes hold the mic via CoreAudio, not the calendar), local whisper.cpp transcription with the API only as fallback, and a pipeline engineered so that any single failure still preserves the recording. Only the LLM summarization call leaves the machine. The differentiator versus Granola is privacy and resilience, not cloud features.

## Operating Context

- Runs as a menu bar agent with no dock icon or main window. The three interactive surfaces are: the menu bar dropdown (`MenuContent`), the preferences window (`SettingsView`, the `Settings {}` scene), and a floating Record / Not now panel that appears when a meeting is detected (`MeetingPrompt`).
- Output: `~/MeetingNotes/YYYY-MM-DD-HHMM.md` plus the `.m4a` beside it.
- Requires macOS TCC permissions: Screen Recording (for ScreenCaptureKit system audio), Microphone, and Calendar (read-only context). Permission state is surfaced in the UI and re-read live.
- Recovery is automatic and mostly silent: backfill sweeps regenerate failed summaries; orphaned captures from crashes are reprocessed on launch.

## Capabilities and Constraints

- Menu states reflect a state machine: idle, working ("Recording", "Starting…", processing), saved, recovered, retrying, and error/alert phases.
- Auto-start on meetings is opt-in (toggle in Settings); trigger is microphone usage by a non-ignored app, matched by bundle-ID prefix, with the calendar supplying title/end-time as context only.
- Launch at login via `SMAppService`; source of truth is the service status, not a stored bool.
- The app must never block on modals during recording; quit during recording/processing is intercepted so the pipeline saves first.
- Diagnostics go to `~/Library/Logs/Alpiste/alpiste.log`. Never log secrets or meeting content.
- All UI copy is in English (per project convention); code and identifiers in English.

## Product Principles

1. Never lose a recording. Every failure path still writes the `.md` and keeps the audio; the UI must never imply loss that did not happen (a retry in flight is not "lost").
2. Invisible until it matters. As a menu bar agent, the app stays out of the way and interrupts only for a real decision (permission, or a meeting to record).
3. Local and private by default. No accounts, no cloud, no telemetry; only the summarization call leaves the machine, and that boundary is a selling point to preserve.
4. State honesty. Every UI surface tells the true current state (recording, processing, saved, recovered, retrying, failed) and reflects live permission status; no stale or reassuring-but-false labels.
5. Native macOS restraint. Follow HIG for menu bar utilities; no custom `NSWindow` with interactive controls (crashes menu bar apps), no invented web patterns.

## Accessibility & Inclusion

Native AppKit/SwiftUI controls carry system accessibility. Must support Dynamic Type/system font sizing, VoiceOver labels on custom controls (the meeting prompt buttons, status rows), full keyboard operability (the menu and Settings are keyboard-reachable), Reduce Motion, and both light and dark appearance. No product-specific standard was set beyond meeting the macOS system baseline.
